01 / REFERENCE

OpenAI Codex 的入口、上手、能做的事、价格与用量限制、对比、安全（想深入了解的人）

以下内容是想确认 Codex 本身时再展开看的。它们都不影响与 SIMY 的连接。

OpenAI Codex 是什么：与 ChatGPT 的区别、与旧 Codex 的区分包含在 ChatGPT 方案中的智能体

Codex 是什么

OpenAI Codex 是 OpenAI 提供的 AI 智能体。ChatGPT 是“问了就答”，Codex 是“交代了就干”。它在你的电脑或云端的工作环境里读取文件、执行命令、操作浏览器、做出成果。最初为软件开发而生，但到了 2026 年，随着桌面应用和插件的加入，已扩展到制作资料、起草邮件等不写代码的工作。

与 ChatGPT 的区别

ChatGPT 在对话中返回答案。Codex 返回的不是答案，而是“做好的东西”。比如交代“调研 A 公司并做一份提案资料”，ChatGPT 会用文字给出结构方案，Codex 则会做出一个 Slides 文件。两者用同一个 ChatGPT 账户，额度共享。

别把名字搞混

  • 旧 Codex（2021 年）：作为 GitHub Copilot 早期模型使用的代码补全语言模型。2023 年已停止提供，与现在的 OpenAI Codex 是不同的产品。
  • GPT-5-Codex 等模型名：这是在 Codex 中可以选择的模型名称。作为产品的 Codex 和作为模型的 GPT-5-Codex 属于不同层级。

与 ChatGPT Work 的区别

ChatGPT 桌面应用有 Chat、Work、Codex 三种模式。Work 是完成调研、资料等各类工作成果的智能体，Codex 是擅长处理文件和命令的智能体，两者共享额度。不写代码的人拿不准用哪个时：需要读写文件或操作 Chrome 就用 Codex，想在对话的延长线上拿到成果就用 Work。

能用中文吗

可以。应用界面以英文为主，但指令和成果用中文都没问题。AGENTS.md 和 skills 也能用中文写。

上手步骤：登录、AGENTS.md、审批模式桌面应用只需下载和登录两步

从桌面应用开始（写给不写代码的人）

  1. 下载并安装。从 OpenAI 的 Codex 页面安装 Windows 版或 Mac 版。
  2. 用 ChatGPT 账户登录。Plus 及以上方案无需 API 密钥。浏览器会打开，授权即可完成。
  3. 选择工作文件夹。指定允许 Codex 读写的文件夹。Drive 的文件夹、或整理好资料的文件夹就足够。
  4. 决定审批模式。一开始用“修改前确认”的设置，熟悉后再放宽到“自动”。
  5. 用中文交代一件事。像“用这个文件夹里的案例，做一份给 A 公司的提案资料”这样，按托人办事的说法就行。

从 CLI 开始（写给工程师）

装好 Node.js 后，在终端运行 npm install -g @openai/codex，输入 codex 登录。Windows 的原生支持在推进中，但在 WSL 上运行更稳定。

AGENTS.md：写下做法的文件

在工作文件夹里放一个名为 AGENTS.md 的文本文件，Codex 每次都会读取其中的规则（命名、结构、禁止事项）再工作。像“提案资料 12 页，最后以下一步收尾”这样的业务格式也能写。使用 SIMY 时，它会从对话中学习这个格式，不写也能开始。

第一件就顺利的交代方式

  • 告诉它材料在哪里。先写明“用 Drive 的‘案例’文件夹”这类允许读取的位置，能减少到处找的时间和用量。
  • 给一个成品的样子。附上上次的资料或一封样例邮件，结构和措辞就会统一。
  • 定好可以停下的地方。写上“不要发送”“做到草稿为止”，审批次数会减少，交出去也更安心。
  • 以文件形式接收结果。不要聊天里的长文，而是做成 Slides 或 Docs 文件，就能直接分享。

审批模式与沙箱

Codex 可以在三种模式间切换：修改文件或对外操作前请求批准的“确认模式”、在工作文件夹内可自行推进的“自动模式”、全部交给它的“完全访问”。无论哪种模式，工作都在沙箱中进行，对指定文件夹之外和网络的操作会受到限制。

能做的事：skills、MCP、Chrome 操作、插件、定时Gmail 草稿、Drive、Sheets、Slides、Notion、Calendar、Slack

通过插件连接的业务应用（截至 2026 年 10 月）

  • Gmail：读邮件，把回复或新邮件存为草稿。发送由你来按。
  • Google Drive、Sheets、Slides：读取文件夹中的文件，更新表格，制作幻灯片。
  • Notion：读写页面和数据库。适合作为纪要存放处或客户备忘。
  • Google Calendar：读取日程，给出候选日期，准备邀请。
  • Slack：读取频道，起草发布内容。
  • Chrome 操作：打开 Chrome 调研网站、填写表单、读取页面。也能用来查看需要登录的业务系统。

skills、MCP、子智能体

skills 是把步骤和判断标准打包、可重复使用的一组指令。把“周报怎么做”“纪要格式”做成 skill，就能省去每次说明。MCP（Model Context Protocol）是把外部工具和数据接入 Codex 的通用标准，插件里没有的服务（Figma、内部数据库等）从这里补充。较长的任务可以拆给子智能体并行推进。

定时、计划模式、评审

定时是以时间为起点重复任务的功能，比如“每周五核对当周的邮件、Slack 和销售记录，起草给上司的 Slack 周报”。计划模式是在执行前只让它给出步骤和影响范围供你确认的模式。代码评审是让 Codex 检查 GitHub PR 的功能，面向开发团队。

不写代码的工作中的用法（示例）

  • 公司调研：用 Chrome 读对方公司的网站和新闻，把要点和议题整理进 Docs。
  • 提案资料：用 Drive 里的案例和价目表，在 Slides 做 12 页。以上次的资料为样本统一结构。
  • 纪要与汇报：交给它转录稿，按决定事项、负责人、期限的格式做纪要，把给上司的摘要做成 Slack 草稿。
  • 日程协调：从 Calendar 的空档中挑 3 个候选，把邀请邮件存为 Gmail 草稿。
  • 更新表格：读取 Sheets 的进度表，反映会上决定的变更，列出差异。

与 SIMY 的关系：定时以时间为起点，即便如此，写第一条指令的还是你。SIMY 从会议和聊天中接住起点。正因为 Codex 的插件能做 Gmail 草稿和 Slides，SIMY 才能专注于决定“何时、做什么、做到哪一步”。

用量限制的机制

  • Plus和标准Business有五小时用量额度，也可能适用每周限制。Pro目前没有五小时限制。消耗取决于模型和任务，请在用量面板中查看剩余额度及重置时间。
  • 消耗量随模型和任务变化：越聪明的模型、越长的对话、越大的文件消耗越快。日常做资料多数用标准模型就够，只在难的调研时切换到更高的模型，额度更耐用。
  • 额度用完时的选项：等待重置、升级到 Pro、用 API 密钥按量计费、搭配 Claude Code 等其他执行者。
  • 在哪里看用量：桌面应用和 CLI 看用量计，ChatGPT 设置页面可查看各方案的使用情况。

让额度更耐用的诀窍

一条指令里写清材料位置和成品形状、长对话拆成新线程、调研和制作分成不同任务。做到这三点，同样的工作消耗也会明显减少。模型好比画家的功力，推理级别好比作画花的时间。在意用量时，就调低推理级别。SIMY 交给 Codex 时，也会直接传入学到的格式，返工带来的消耗更少。

建议搭配使用

Codex 和 Claude Code 运行在不同的方案上。为了在一方模型不稳定或额度用完时工作不停，越来越多人两个都熟悉。两个 CLI 之间，可以在同一个文件夹里交替使用。

SIMY 的定位：SIMY 可以让 Codex 和 Claude Code 都作为执行者。云端用你自己的 ChatGPT 账户运行 Codex，电脑上 SIMY 桌面应用也能使用 Claude Code。无论用哪个运行，回到你手上的都只有判断。ChatGPT 本身的用法整理在ChatGPT 使用指南里。

安全与注意事项：不用于训练的设置、沙箱、审批用于工作前要把握的 3 点
  • 不用于训练的设置：在 ChatGPT 设置 →“数据控制”中关闭“为所有人改进模型”，Codex 的对话也不会用于训练。默认是开启的。Business 和 Enterprise 按合同，业务数据默认不用于训练。
  • 沙箱：Codex 的工作在限制了指定文件夹和网络范围的环境中进行，不会碰文件夹外的文件或未允许的网站。
  • 审批：删除、发送、发布等无法撤销的操作前，Codex 会请求批准。自动批准（俗称 YOLO）除了一次性环境外请避免使用。
  • Chrome 操作：如果在已登录业务系统的状态下使用，建议建一个专用 Chrome 配置文件，用权限较少的账户让它操作。
  • 信息外流：原则上不要把含个人信息或机密的文件夹指定为工作文件夹。如果公司规定了 ChatGPT 的使用范围，请考虑使用 Business 及以上方案。
  • 与 SIMY 的连接：SIMY 通过 ChatGPT 的认证页面登录你的账户，经你授权后连接。根据对话记录生成建议时，正文不保存在服务器上。详情公开于安全和隐私政策。
02 / AFTER THE TASK

用 Codex 忙完一天后，是不是这样

公司调研、提案资料、会议纪要、给上司的汇报。交给 OpenAI Codex，全都做完了。可到了傍晚，还是会发生这些事。

1 第二天早上 第二天，同样的指令

调研→资料→纪要→汇报，做完了。可明天，同样的指令还得自己敲。

2 每次开口时 一边盯着用量

剩 84%。越聪明的模型消耗越快，开口前总要犹豫一下。

3 会议间隙 跑去看做完没有

打开任务列表确认。等你判断的事，埋在聊天记录底下。

Codex 能把一件事做完。“下一件交给它什么”和“确认做完没有”，仍然留在你手上。

03 / WHAT YOU REALLY WANTED

其实你想要的是这样：Codex 的工作之后

同样的 Codex，同样的 ChatGPT 方案。一天结束时，你希望已经变成这样。

✓ 没开口也 会后就已排好

纪要、汇报、客户备忘的更新。走出会议室时，任务已经开始动了。

✓ 不写 AGENTS.md 也 每次都是你的格式

提案资料的结构、汇报的颗粒度。记住第一次的做法，之后都用同样的形状。

✓ 早上一打开 收到建议

“上周做了 3 次的这件事，要不要每次都做？”SIMY 从 Codex 的对话记录里找出来。

! 回到你手上的 只有判断

“按这个金额提案可以吗？”只回来这一个问题，用手机就能回复。

这些，从把 ChatGPT 账户连上 SIMY 的第二天起就会发生。

09 / FAQ

常见问题

OpenAI Codex 可以免费使用吗？

核对于2026年10月3日：Free和Go正在逐步提供桌面应用中的GPT-6 Luna，使用Standard速度。可用入口、模型和额度与Plus及更高方案不同。API密钥使用另行计费。SIMY云端连接的条件需要单独确认。

ChatGPT Plus 能用多少 Codex？

Plus和标准Business有五小时用量额度，也可能适用每周限制。Pro目前没有五小时限制。消耗取决于模型和任务，请在用量面板中查看剩余额度及重置时间。

Codex 的用量什么时候重置？

重置时间取决于方案和额度。请在Codex用量面板或CLI的 /status 中查看剩余用量及重置时间。不要假定所有额度都在首次使用后经过固定时间恢复。

Claude Code 和 Codex，该选哪个？

不必只选一个。Codex 运行在 ChatGPT 方案上，Claude Code 运行在 Claude 方案上，为了在一方不稳定或额度用完时有备选，越来越多人两个都熟悉。SIMY 可以让 Codex 和 Claude Code 都作为执行者。

Codex 的计划模式是什么？

这是不改动文件、先只给出步骤和影响范围的模式。大任务前先确认计划，达成一致后再执行。与审批模式组合，就能细致地决定把什么交出去、交到哪一步。

不是工程师也能用 Codex 吗？

能。OpenAI 表示，Codex 用户中超过两成不是工程师（截至 2026 年）。在桌面应用里用中文交代，就能完成公司调研、提案资料、会议纪要，直到 Gmail 草稿，几乎没有需要看代码的时候。

Codex 的定时功能和 SIMY 有什么不同？

Codex 的定时以时间为起点，重复设定好的任务。SIMY 以会议和聊天为起点，找出其中产生的工作，让 Codex 去推进。每天早上 9 点的固定工作用 Codex 的定时，每次会议都不一样的工作交给 SIMY，可以这样分工。

让 Codex 操作 Chrome 安全吗？

Codex 在沙箱中运行，登录、提交表单等会影响外部的操作前会请求批准。用于工作时，请把握 3 点：不要把审批模式设为自动、使用专用的 Chrome 配置文件、确认不用于训练的设置。

输入 Codex 的内容会被用于 AI 训练吗？

在 ChatGPT 设置的“数据控制”中关闭“为所有人改进模型”，Codex 的对话也不会用于训练。Business 和 Enterprise 按合同，业务数据默认不用于训练。

使用 SIMY，Codex 的使用费要另付吗？

SIMY 连接你自己的 ChatGPT 账户，通过 Codex App Server 推进工作。Codex 的用量计入你自己的 ChatGPT 方案。SIMY 本身的价格请见价格页面。

能用手机使用 Codex 吗？

可以在 ChatGPT 的 iOS、Android 应用中查看 Codex Cloud 的任务，并交代新任务。使用 SIMY 的 iOS 应用，Codex 推进的工作中只有等待判断的事会送到手机上，批准后即可回复。
