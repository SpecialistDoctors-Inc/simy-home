# HPローカル編集：はじめ方と使い方

2026年11月6日・試用向けの案内です。現在の試験アカウントで、接続、下書き保存、確認ページへの反映、通知メールの受信、途中停止後の復旧を確認しています。手元の確認画面の右下メニューは接続テストまで確認済みです。Codexの会話内カードも、本人のクリックとサーバー側の完了記録まで確認済みです。本人がCodex内の公開カードで確定し、本番への反映と通知メールの受信まで確認できました。

## 用意するもの

- Codexを利用できるアカウントとパソコン。
- 運用担当に登録したGoogleアカウント。
- 運用担当から案内された「HPローカル編集」プラグインの固定版。GitHubの管理画面とは別のものです。

Gitの導入、GitHubアカウント、SIMYアカウントは不要です。対応するパソコンはmacOSまたはLinuxです。Windowsは現段階では未対応です。Python 3が使えることは、Codexと運用担当が導入時に確認します。

## 最初の接続

1. 運用担当が案内した固定版を、Codexと一緒にダウンロード・検証して導入します。Gitを使った取得や、既存設定の上書きは行いません。
2. HPローカル編集の接続画面で、本人がGoogleにログインします。Codexに接続先の本人情報と、編集できるサイトを確認してもらいます。
3. **Google Driveも別に接続します。** HPローカル編集と同じGoogleアカウントを選び、Codexに両方の接続プロフィールを照合してもらいます。HP側のログインだけではDrive接続は完了しません。
4. 編集したいサイトが正しいことを確認し、専用の作業フォルダーを新しく作ってもらいます。ファイルの取得・検証はCodexが行います。

接続先や対象サイトが表示されない、Googleアカウントが一致しない場合は、ファイルの受け渡しを止めて運用担当に連絡してください。似た名前のDriveフォルダーを選び直したり、共有範囲を広げたりする必要はありません。パスワードや認証コードを会話に貼り付けないでください。

今回の試用版は **0.2.0** です。[固定版ZIP](https://codeload.github.com/SpecialistDoctors-Inc/simy-hp-skills/zip/53432225cc89cdf0f19d60cba75b4fc2dd536197) を使います。ファイルの確認値（SHA256）は `b9713b57fd8352d7e6186b79258f7dbe2da69dd1b46c680bccff5a700dbb1445` です。Codexに照合してもらうための情報で、ご自身でコマンドを入力する必要はありません。

導入だけを依頼するときは、次のように伝えられます。

> 運用担当から案内された固定版を、Gitを使わずに検証・導入してください。HPローカル編集とGoogle Driveの接続が同じ本人か、対象サイトが正しいか確認してください。今回は接続確認だけで、編集・保存・公開は行わないでください。

## 普段の編集と保存

作業フォルダー内の `site/` がホームページの編集用ファイルです。Codexに「どのページの、何を、どう変えたいか」を伝えます。文章、画像、見た目やページの追加を、普通のファイルとして一緒に直します。

> 診療案内の説明文を、次の文章に変更してください。変更した箇所を見せ、表示を確認してから下書き保存してください。本番公開はしないでください。

Codexは実際の変更を確認し、まとまりごとに下書き保存します。保存時の短い履歴メモも、会話と実際の差分からCodexがまとめます。お客様がGitを操作したり、毎回コミットメッセージを考えたりする必要はありません。

「受付済み」「処理中」は保存完了ではありません。Codexが保存完了の結果を読み取り、手元の作業フォルダーへ反映したところまで確認します。保存用ファイルを作った後に追加で編集した内容は、その保存には含まれません。追加編集は手元に残し、次の保存で扱います。

## 手元で変更を確認する

Codexに確認画面を開いてもらい、文章や画像を直しながら見比べます。ファイルを保存すると、開いている画面へ自動反映します。毎回クラウドへの保存・配備を待たずに確認できます。右下のメニューは折りたためます。自動反映・確認ページの準備・公開なしの接続確認と、受付直後に処理が停止したあとの再開を実際の画面で確認済みです。本番公開は、確認した内容への本人の確定操作が必要です。

手元で見えている変更、下書きとして保存した変更、公開前に検証を終えた内容は別の段階です。公開確認では必ず検証済みのページを表示します。手元に未保存の変更がある場合は、先にCodexへ保存と確認ページの準備を依頼してください。

## 下書き保存・確認ページ・公開の違い

| 操作 | 何が起きるか |
| --- | --- |
| 下書き保存 | 編集内容を控えとして保存します。一般向けのホームページは変わりません。 |
| 確認ページの準備 | 保存した変更を検証し、内容を確認するページを用意します。下書き保存とは別の依頼です。 |
| 本番公開 | 確認した内容を、本人の公開確認カード操作を経て一般向けのホームページへ反映します。 |

確認ページの準備は試験アカウントで利用できます。本番公開は、確認した版を本人が公開カードで確定して行います。

確認ページが用意されたら、パソコンとスマートフォンの表示、文章、リンク、画像を確認します。直したい点があればCodexに戻して編集・保存し、新しい確認ページを作ります。古い確認ページへの公開確認は使い回しません。

公開するときは、Codexの会話内に出る確認カード、または手元の確認画面の右下メニューから、対象サイトと確認済みの内容を読み、**本人が公開ボタンを押します**。どちらも同じ公開処理につながります。会話の「公開して」や履歴メモだけで公開完了にはなりません。カードが表示されない場合は運用担当へ連絡し、別の方法で確認操作を飛ばさないでください。クリック後も処理状況を確認し、公開済みになったことと、実際のホームページへの反映を確認します。

## 会話で頼むときの例

最初に、編集するサイトと作業フォルダーを確認してもらいます。その後は、次のように伝えられます。

> お知らせの最後に「来月の診療予定は近日お知らせします」を追記してください。手元の確認画面を開き、保存するたびに表示へ反映してください。内容を確認したら下書き保存まで進め、本番公開はまだしないでください。

公開前の確認は、次のように依頼します。

> 保存済みの変更から確認ページを作り、結果を確認してください。公開できる状態になったら、Codexの確認カードかローカル画面のメニューで公開内容を見せてください。

カードとメニューは同じ公開操作につながります。両方で操作しても、同じ内容の公開依頼を増やすことはありません。公開完了は処理状況と実際のホームページで確認します。

## 中断・エラーが起きたら

まず作業フォルダー全体を残してください。`site/` と、原本・保存待ちの情報を持つ `.hp/` はセットです。`.hp/` やロックファイルを削除してやり直さないでください。

| 状況 | Codexへの依頼 |
| --- | --- |
| 通信切断、処理中のまま、保存したか不明 | 前回と同じ受付番号（操作ID）で状態を調べる。新しい保存依頼や新しいIDを作らない。 |
| アップロード前に中断 | 保存待ちの同じファイルと操作IDから再開する。途中で作り直さない。 |
| サービス側では保存済みだが、手元で完了にならない | 保存結果を読み直し、その結果を手元へ反映する。サイトへの保存は再送しない。 |
| ほかの編集と競合した | 両方の変更を残してCodexと内容を確認する。勝手に上書きしない。 |
| 接続期限・権限・対象サイトのエラー | 表示された理由を運用担当へ伝える。別のアカウントやフォルダーで続行しない。 |
| メールや記録の更新が見つからない | 操作の状態を確認する。通知のために保存や公開を送り直さない。 |

再開時は、例えば次のように依頼できます。

> 前回の操作IDで状態を確認してください。保存済みなら、その保存結果だけを手元へ反映してください。保存したか不明な間は、新しい依頼を送らず、作業フォルダーと保存待ちファイルを残してください。

保存が「実行されずに拒否された」と確認できた場合に限り、Codexと運用担当が、最新の内容を別の新しい作業フォルダーへ取り直して変更を移します。古い作業フォルダーも残します。

公開のキャンセルは、すでに反映されたホームページを元に戻す操作ではありません。公開結果が不明、または表示に問題がある場合は、状態確認と運用担当への連絡を先に行ってください。
