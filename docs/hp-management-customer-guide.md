# 医院向け：CodexによるサンプルHP更新受付テスト手順

更新日：2026-10-30

SIMY担当者と一緒に設定する場合は、[設定の順序と役割の一覧](hp-management-start-here.md)も参照してください。

この文書は、CodexとGoogle Sheetsを使うサンプルクリニックの手動試験専用です。
ホームページで直したいことをCodexに伝えると、必要事項を確認し、医院専用の
Googleスプレッドシートに依頼を残します。SIMYが確認用ページを用意し、医院が
内容を確認した後に本番公開へ進める運用です。

**通常のChatGPTから依頼し、医院がCodex・ローカルスキル・Google/GitHub/AWSの
設定をしない入口は、まだ提供していません。** その入口ではSIMYが対象サイト、
利用者、Google実行接続をサーバー側で管理します。初回の本人認証・権限確認は
残る想定です。この文書の手順を、その将来の通常利用に使わないでください。

現在はサンプルクリニックでの手動試験用です。接続・スキル導入までは
準備できますが、実医院の依頼受付にはSIMY側の医院・利用者登録が必要です。
医院向けの登録手続きは未提供で、自動着手・自動メール通知も未接続です。
サンプル試験ではSIMY担当者が同席し、試験対象を確認して進めます。

## 1. SIMYから利用開始情報を受け取る

次の情報をSIMY担当者から受け取ってください。不明なものはCodexに推測させず、
SIMYに確認します。

| 受け取るもの | 用途 |
| --- | --- |
| 医院名・サイトID | どの医院のホームページを扱うか確認する |
| 専用スプレッドシートのURL | 依頼と対応結果を保存・確認する |
| 利用するGoogleアカウント | 上記シートへの編集権限をSIMYから付与してもらう |
| 確認用URL・本番URL | 修正案と公開済みのページを区別する |
| SIMY担当窓口・対応の受け渡し方法 | 受付後の着手依頼や接続エラーを連絡する |
| 通知先メールの確認状況 | 将来の通知先を確認する。現時点で自動送信はされない |
| 利用区分 | 「サンプル試験」か、登録済みの実医院向けサービスか |

医院側の端末にAWSやGitHubの管理認証を入れる必要はありません。
Dockerも医院の通常利用には不要です。

## 2. Codexを使えるアプリを用意し、ログインする

1. [公式デスクトップアプリ案内](https://developers.openai.com/codex/app)から、
   使うOSに対応するアプリをインストールします。
2. 自分のChatGPTアカウントでサインインします。
3. Codexで新しいチャットを開始します。作業フォルダーを選ぶ場合は、
   HP更新用の空フォルダーを用意します。
4. 「ホームページ更新の準備をします。まず返答してください」と送り、
   応答することを確認します。

2026-10-30に確認した公式案内は「ChatGPT desktop app」内でCodexを選ぶ
説明になっています。既にCodexアプリを利用している場合は、そのCodex環境から
続けてください。組織で機能が制限されている場合は管理者へ確認します。

**確認結果：** 本人のアカウントでCodexから応答が返る。
SIMYへパスワードやログインコードを送る必要はありません。

## 3. Google Driveを接続する

1. アプリの **Plugins** から **Google Drive** を探し、インストールします。
   Google Sheetsの読み書きもこのプラグインを使います。
2. 接続を求められたら、手順1でSIMYに伝えたGoogleアカウントを選び、
   表示されたアクセス権を確認して接続します。
3. 新しいCodexチャットを開始します。
4. 下記の `<…>` を実際の値に置き換えて送ります。

```text
ホームページ更新のためのGoogle接続を確認してください。
専用シート：<SIMYから受け取ったスプレッドシートURL>
利用するGoogleアカウント：<SIMYに伝えたGoogleアカウント>

Google Driveプラグインで、実際の接続先プロフィールと、このシートの名前・
タブ名・RequestsとEventsの4行目の見出しを確認してください。
指定アカウントと一致するかも報告してください。
この段階では読み取りだけを行ってください。
```

**確認結果：** 接続先が一致し、`ご利用ガイド`・`Requests`・`Events` を読める。
読み取り成功だけでは編集権限や医院登録の完了までは確認できません。

ブラウザーでシートを開けても、Codexの接続先が別アカウントだと失敗します。
過去にGoogleを接続したChatGPTアカウントでは、その接続が再利用される場合が
あるため、この確認は省略しません。
操作画面の詳細は[公式プラグイン案内](https://learn.chatgpt.com/docs/plugins)を参照します。

## 4. HP更新受付スキルを入れる

次をCodexに貼り付けます。この版はサンプル試験で確認した固定版です。

```text
SIMYのホームページ更新受付スキルをインストールしてください。
取得元は SpecialistDoctors-Inc/simy-home、
リビジョンは 80a04f7f3fe143df06767a4ae1eaf786e1297519、
パスは examples/hp-management/skills/hp-customer-intake です。
公式のskill-installerが利用できれば、それを使ってください。
同梱のreferencesも含めて導入し、既存の同名スキルがあれば上書きせず確認してください。
完了後、利用開始に必要な接続・医院の登録情報を教えてください。
このメッセージでは、シートへの依頼登録、本番公開、メール送信は依頼しません。
```

導入後、新しいチャットで次を送ります。

```text
hp-customer-intakeスキルを使って、HP更新の受付準備を確認してください。
スキル本文と同梱のworkbook-contract.mdを読めるか、Google接続を使えるか、
SIMYが確認した医院・利用者・専用シートの対応を取得できるかを報告してください。
不足している場合は書き込まず、何が不足しているか教えてください。
```

**確認結果：** スキルが認識され、登録済みの対象を確認できる。
現状は登録サービスが未実装のため、通常の受付ではここで止まる場合があります。
それを正常な利用開始と扱わず、SIMY担当者へ結果を渡してください。

スキルは「何を確認し、どう依頼を整理するか」という手順です。インストール
しても、医院の登録、Googleへのログイン、本番公開の権限は追加されません。

## 5. 更新を依頼する

SIMYが利用区分と対象を確認した後に進みます。サンプル試験は担当者の同席下で
行います。実医院の登録が未完了のまま、試験用の設定を流用しないでください。

通常は「どこを、どう直したいか」を伝えれば始められます。
たとえば「アクセスページの『診療時問』を『診療時間』に直して」です。
Codexが必要なことだけ質問するので、文章・日付・画像などを補足します。

初回のサンプル試験には、次のような依頼を使います。

```text
hp-customer-intakeで、SIMYが確認済みのサンプルクリニックへの更新を依頼します。

確認用ページのお知らせ欄に、次の案内を1件追加してください。
タイトル：ホームページ更新受付の動作確認
カテゴリ：お知らせ
本文：Codexからホームページの更新を依頼するテストです。
      実際の診療予定には関係ありません。
掲載日：<今回の試験日 YYYY-MM-DD>
反映範囲：確認用のdev環境のみ。受付後、SIMYが手動で着手します。
画像・予約リンク・診療時間の変更：なし
表示期限：この試験では設定しません。削除は別途依頼します。
合格条件：PCとスマートフォンで本文を開いて読め、既存のお知らせが残ること。

不足事項がなければ、確認済みの専用シートに依頼とready_for_devイベントを
登録し、再読込して、依頼ID・revision・登録内容を教えてください。
本番公開とメール送信はこの依頼に含みません。
```

**確認結果：** Codexが依頼ID、revision、保存した内容を返す。
「登録予定です」という応答だけでは受付完了ではありません。
接続先や権限が確認できない場合は書き込まずに止まります。

現在はシートに登録しても開発側Codexが自動起動しません。手順1で決めた方法で、
SIMY担当者に依頼IDとrevisionを渡してください。

## 6. 対応結果と確認用ページを見る

```text
hp-customer-intakeを使って、確認済みの専用シートから
依頼ID <依頼ID>、revision <番号> の対応結果を確認してください。
確認用URL、変更内容、実施したテスト、未対応事項を教えてください。
dev_preview_readyに記録されたsource SHA、artifactHash、artifact IDも
承認対象の識別情報として保持してください。
```

SIMYから確認準備完了の案内を受けたら、確認用URLをPCとスマートフォンで開き、
文章・日付・リンクなどが依頼どおりか確認します。
この時点は確認用ページへの反映で、本番公開の完了ではありません。

修正が必要な場合は、同じ依頼IDを添えて「ここを直したい」と伝えます。
Codexが変更した依頼を新しいrevisionとして記録します。
以前の依頼行や対応記録を直接消す必要はありません。

## 7. 内容を確認して、本番公開を依頼する

**現在のdevまでの試験には含まれません。** サンプルの公開試験も行う場合は、
SIMY担当者に別途開始を依頼します。実医院向けの承認受付は、医院・利用者の
登録手続きが未提供のため、まだ利用開始できません。

サンプルの公開試験では、担当者が本人の公開意思を確認し、シートとは別の
非公開記録に残します。通常の受付スキルに承認イベントを書かせるだけでは
この手続きは完了しません。まずCodexへ次を送り、確認対象を表示させます。

```text
依頼ID <依頼ID> の確認用ページを見ました。
本番公開を判断できるよう、最新のrevision、変更内容、確認用URL、
source SHA、artifactHash、artifact IDをまとめてください。
まだ本番公開の承認は記録しないでください。
```

内容が正しいと確認できたら、**その表示された版の識別情報を省略せず**、
SIMY担当者との確認済みの連絡経路で次の文面を伝えます。
Codexに文面を用意させる場合は、まず下書きとして受け取ってください。

```text
サンプルクリニックの公開試験として、次の内容を本番URLへ公開することを承認します。
依頼ID：<依頼ID>
revision：<番号>
確認用URL：<今回確認したURL>
source SHA：<表示された完全なSHA>
artifactHash：<表示されたhash>
artifact ID：<表示されたID>
本番URL：https://sample-clinic.simy.one
```

SIMYは[管理側の公開手順](hp-management-setup-guide.md#9-承認された版を本番へ公開する)
で本人の承認と対象の版を記録・照合し、保護された公開処理を実行します。
承認後に内容や版が変わった場合は、新しい確認用ページを確認します。
公開後は本番URLと公開確認結果を受け取ってください。

## 困ったとき

| 状況 | 確認・対応 |
| --- | --- |
| シートを開けない、403になる | Codex側のGoogle接続先と、SIMYが編集権限を付けたアカウントを照合する |
| Google Driveが見つからない | Pluginsと組織の利用設定を確認する。チャットを新しくする |
| スキルが見つからない | 新しいチャットで確認する。導入した端末・環境と現在の環境が同じか確認する |
| スキルを保存できない | SIMYにエラーを渡す。スキル保存先だけに必要な書込許可を付ける |
| 医院・利用者の登録を確認できない | SIMYの登録作業が必要。サイトURLやメールを書き足すだけでは解消しない |
| 依頼したが確認用ページが変わらない | 依頼IDとrevisionで受付記録を確認し、SIMY担当者へ着手を依頼する |
| メールが届かない | 現状の自動通知は未接続。シートまたはCodexで結果を確認する |

詳細な設定と現時点の制約は、SIMY担当者向けの
[初期設定・運用手順](hp-management-setup-guide.md)を参照してください。
