# 医院向け: HP更新を依頼する

この手順では、医院の担当者が Codex と共有 Google Sheets で更新要望を伝え、dev 確認ページをレビューします。SIMY のアカウント、GitHub、AWS、Docker は必要ありません。

## 1. Codex にログインする

Codex を導入し、医院で使う ChatGPT アカウントでログインします。CLI を使う場合は、公式の [Codex CLI ガイド](https://learn.chatgpt.com/docs/cli) に従って `codex` を起動し、初回のブラウザー認証を完了してください。ログイン方法やデバイスコード認証は、[公式の認証ガイド](https://learn.chatgpt.com/docs/auth)を参照します。

共有端末では、前の利用者のログイン状態で続けず、プロフィールで利用中のアカウントを確認します。認証情報やパスワードを Sheet に記入しないでください。

## 2. Google Drive と共有 Sheet を接続する

1. Codex の Google Drive 接続を有効にし、開発・運用担当から共有された医院用 Google アカウントで認証します。
2. 新しいチャットで、次のように接続確認を依頼します。

```text
Google Drive 接続で <共有Sheet URL> を読み取ってください。
編集はせず、シート名と `ご利用ガイド`、`Requests`、`Events` の3タブ、
各データタブの見出しが4行目にあることだけを報告してください。
アクセスできない場合は、どの権限が不足しているかを説明してください。
```

`Requests` と `Events` は、見出しが4行目、実データが5行目からです。1〜3行目の説明文を依頼データとして扱わないでください。

読取りできても、外部サービスへの書込みが許可されているとは限りません。初回だけは開発・運用担当の監督下で通常の対話型 Codex セッションから1件を追記し、表示された承認内容と読戻し結果を確認します。自動実行のために保護や承認設定を無効にしないでください。

## 3. 受付スキルを導入する

開発・運用担当から渡された **固定済み候補版** の `hp-customer-intake` を導入します。タグまたはコミットSHAを必ず指定し、「最新」だけで導入しないでください。Codex のスキルは再利用可能な手順と補助資料のまとまりです。一般的な導入方法は [公式の Skills & Plugins ガイド](https://learn.chatgpt.com/docs/skills-and-plugins) を参照できます。

導入時の依頼文:

```text
<配布元> の hp-customer-intake スキルを、
固定版 <承認済み候補タグまたはコミットSHA> で導入してください。
同梱の references も読み、既存の同名スキルを確認なしに上書きしないでください。
導入後はサイトの変更、公開、メール送信を行わず、認識できたスキル名だけを教えてください。
```

## 4. 更新を依頼する

Codex に、変えたい場所と内容を普段の言葉で伝えます。文章修正なら「どのページの、どの文を、何に変えるか」を書くと早く進みます。公開期間があるお知らせは、開始日・終了日・タイムゾーンも伝えてください。

```text
<共有Sheet URL> にあるサイト <site_id> の更新を依頼します。
対象: <ページURLまたはページ名>
変更内容: <現在の内容と希望する内容>
希望時期: <必要な場合のみ>
確認条件: <画面で確認したいこと>

hp-customer-intake の手順に従い、不足情報だけ質問してください。
内容が固まったら Requests と Events に追記し、依頼ID、revision、保存した内容を読み戻してください。
実装・GitHub操作・AWS操作・本番公開・メール送信は行わないでください。
```

Codex は不足する情報を質問し、`Requests` に依頼、`Events` に質問・回答・引継ぎを追加します。修正が必要になった場合は、過去の行を直すのではなく新しい `revision` を作ります。

読み戻された **依頼ID・revision・内容** が意図どおりか確認してください。Sheet の共有権限とセルの値だけでは、誰が本番公開を指示できるかは証明されません。現在の運用では、指定した医院用 Sheet を指定した Google アカウントと共有していることを確認しますが、これは暗号学的な本人確認ではありません。

## 5. dev を確認する

開発・運用担当が作業すると、`Events` に `dev_preview_ready` として、dev URL、source SHA、artifact hash、テスト結果が記録されます。医院は dev ページを開き、依頼内容と確認条件をレビューします。

問題があれば修正希望を伝えます。問題がなければ、表示中の **依頼ID・revision・source SHA・artifact ID・artifact hash** を指定して、人に確認済みであることを明示します。Sheet の状態や `approved` という文字だけで公開を許可しないでください。

本番は、レビューしたものと完全に同じ成果物であることを開発・運用担当と GitHub の保護された公開環境が照合してから進めます。医院の担当者が GitHub や AWS の認証情報を扱う必要はありません。

## 6. 通知と自動化について

メール通知と自動監視は、現時点で完了・検証済みではありません。連絡が必要なときは開発・運用担当に依頼してください。Codex のローカルな定期実行を将来使う場合でも、端末の電源と Codex アプリの稼働が必要で、常時稼働のサービスにはなりません。詳しくは [公式の Scheduled tasks ガイド](https://learn.chatgpt.com/docs/automations) を参照してください。
