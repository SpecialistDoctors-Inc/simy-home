# Shared site header contract — 2026-10-07

## System identity and frozen scope

Purpose: every visitor to an ordinary public SIMY page receives one clear, common header with usable navigation, account links and app destinations. Japanese pages use Japanese labels; English pages use English; Hindi, Spanish, French and Simplified Chinese retain the existing English header while explicitly identifying the English-only sales destination.

- System: static `simy.one` public-site header, generated by `scripts/site_header.py` and styled/enhanced by `site/site-header.css` and `site/site-header.js`.
- Baseline: `main@4b121bf146a7331ae31f43c93818de8a73c655af` (the compact shared header).
- Proposed change: branch `codex/header-locale-contract`, Draft PR #131. A final evidence receipt binds observations to the committed branch HEAD; this document does not claim a self-referential commit SHA.
- Beneficiaries: public visitors who need to understand and use navigation, including keyboard and no-JavaScript users; reviewers and maintainers who need an unambiguous acceptance oracle.
- Human decision: the requester approved the shared-header design and implementation, commit/push and updating Draft PR #131. Assurance level 3 (`assurance-ascending-v2`) was selected for bounded, reversible runtime navigation.
- Authority boundary: local implementation, evidence, commit/push and Draft PR update are allowed. Merge, deployment, production writes, customer messages, authentication-policy changes and knowledge-rule publication are not.
- Source criteria: `AC-1`, `AC-2.work`, `AC-2.language`, `AC-2.layout`, `AC-2.account`, and `AC-3`. Broader marketing-page work and production verification remain outside this PR.

## Epistemic status

Required:

- `AC-1`: all 171 eligible public HTML pages contain exactly one generated shared header without unrelated body or SEO changes.
- `AC-2.work/language/layout/account`: the header remains usable across desktop/mobile, Japanese/English and the four fallback locales, JavaScript/no-JavaScript and keyboard interaction; sales and existing account/store destinations remain honest.
- `AC-3`: the 12 applicable specification views, authentic user/system evidence, independent review and exact-revision SQM result are reconciled while the PR remains Draft and gaps remain visible.

Intended design:

- Reuse native `<details>` so controls and destinations remain reachable without JavaScript.
- Use one generator and one CSS/JavaScript pair rather than page-specific headers.
- Translate header copy only for Japanese. The other four non-English page locales continue to show English header copy; this PR does not invent missing translations.
- Keep navigation local and static. Account and App Store links hand off to their existing external owners; the header does not authenticate, persist or submit account data.

Observed in the candidate source:

- `needs_header()` excludes the authentication callback, redirect pages and documents without a body; regression checks count 171 eligible pages.
- The generated DOM carries English/Japanese visible-label and accessible-name values. Runtime locale changes synchronize them from `html[lang]`.
- JavaScript opens the outer menu on desktop, closes it on mobile, keeps only one inner dropdown open and supports Escape, focusout, outside-pointer and link-activation closure.
- The sales destination is Japanese at `/for/sales/` and otherwise English at `/for/en/sales/`; fallback locales visibly say `For sales (English)`.

Unknown or deliberately unclaimed:

- Production behavior is not observed by this Draft-only task. Local external requests are blocked or made inert, so authentication, App Store availability and third-party services are not verified.
- Physical Safari/iPhone behavior is unobserved.
- Breakpoint focus recovery follows the conservative keyboard contract below. Physical-device and external-service guarantees remain separate.
- The current SQM knowledge bundle has zero applicable `simy-home` rules. A signed `no_applicable_rules` result establishes proof integrity, not feature or incident coverage.

## Observable interaction contract

### AC-1 — shared header on eligible public pages

- Actor/goal: a public visitor opens any ordinary public page and needs the same recognizable navigation before using the page body.
- Context/preconditions: the requested file contains a `<body>` and is not `auth-callback.html` or an HTTP-refresh redirect. The static header assets are part of the same site revision.
- Trigger/reachable entry: direct URL, internal link or reload of an eligible page.
- Perceived information: one SIMY brand/header, locale control, primary navigation, account actions and app destinations appear before the retained body.
- Action/control: the visitor may continue into menus or the page body; generation itself is not a visitor-controlled action.
- System response/transition: `site_header.py` replaces the first pre-`main` header/navigation or inserts one after `<body>`, removes the obsolete legal toolbar and pins the shared assets.
- Usable outcome/postcondition: exactly one `.simy-header` exists on each of 171 eligible pages; excluded focused/redirect artifacts remain without it; content outside the generated header and its asset references is retained.
- Next/handoff: `AC-2.*` begins when the visitor operates the header; otherwise the original page body remains available.
- Alternative/failure/recovery: missing, duplicate or stale generated markup fails `site_header.py --check` and repository regression tests. Recovery is to rerun the generator and review the resulting header-only diff, not to hand-edit generated pages.
- Oracle/provenance: `scripts/site_header.py`, `tests/site-audit-regressions.test.cjs`, full repository tests, a body/SEO preservation comparison against the frozen baseline, and rendered 171-page audit bound in the external evidence matrix.

### AC-2.layout — menu, responsive layout and keyboard recovery

- Actor/goal: pointer, touch or keyboard users expose the intended navigation without clipping or losing the path back to a closed state.
- Context/preconditions: the common header is present. JavaScript may be enabled or disabled; widths of 960px and below use the mobile layout and 961px and above use desktop layout.
- Trigger/reachable entry: activate the outer menu summary on mobile/no-JavaScript desktop, then activate Product, Solutions, Resources or Language.
- Perceived information: desktop navigation is inline after enhancement; mobile navigation opens below the bar; the active inner panel is visible and focus has a visible outline.
- Action/control: Enter/click toggles native summaries; Escape closes the innermost open dropdown first and then the mobile outer menu; focus leaving a dropdown, an outside pointer, or activating a link closes applicable menus.
- System response/transition: one inner dropdown may be open at a time. Escape restores focus to the summary it closed. JavaScript sets the outer menu open on desktop and closed on mobile.
- Usable outcome/postcondition: controls remain within the viewport, shared edges differ by no more than 1 CSS pixel where the layout defines alignment, and the visitor can reach or dismiss navigation.
- Next/handoff: selecting a link continues to `AC-2.work`, `AC-2.language` or `AC-2.account`; dismissing returns to the current page.
- Alternative/failure/recovery: without JavaScript, native details remain the recovery path. Script exceptions, overflow, inconsistent geometry, an undismissable panel or missing focus restoration on tested Escape paths fail acceptance. Layout follows the header container width, including 200% CSS zoom where viewport media queries remain desktop. On desktop→mobile, focus inside the menu moves to its visible outer toggle before closure. On mobile→desktop, focus on the hidden outer toggle moves to the first primary navigation summary. Focus outside these affected controls is retained. A header ResizeObserver repeats this synchronization if the media-query notification is missed; repeated same-layout events do not close a manually opened mobile menu.
- Oracle/provenance: `site/site-header.css`, menu-state code in `site/site-header.js`, rendered checks at 320/390/960/1440 CSS pixels, keyboard checks and viewed screenshots in the final evidence root.

### AC-2.language — locale selection and synchronized labels

- Actor/goal: a visitor recognizes the current language, can select any of the six supported locales and receives labels/routes consistent with the resulting page locale.
- Context/preconditions: locale is one of `en`, `ja`, `hi`, `es`, `fr`, `zh-Hans`; legacy pages may change `html[lang]` in place through their existing `i18n.js`.
- Trigger/reachable entry: activate Language and choose an option, or load/reload a page whose HTML already declares a supported locale.
- Perceived information: the summary announces `言語: 日本語` for Japanese and `Language: <name>` otherwise; the current option has `aria-current="page"`; Japanese visible/control labels are Japanese and other locale headers use English.
- Action/control: the visitor chooses one of six explicit links. Existing `hreflang` counterparts are preferred; legacy pages retain the same page with `?lang=<locale>`; otherwise the localized home is the fallback.
- System response/transition: generated no-JavaScript markup already matches its initial locale. With JavaScript, a mutation of `html[lang]` updates visible labels, accessible names, current option, locale code and applicable routes.
- Usable outcome/postcondition: label language, accessible name, current-locale state and destination set agree after initial load and repeated locale changes.
- Next/handoff: the visitor may open another menu, follow a destination or continue reading in the selected page locale.
- Alternative/failure/recovery: an unsupported runtime locale is ignored rather than inventing a mapping. With JavaScript unavailable, the selected language link performs ordinary navigation using the generated alternatives.
- Oracle/provenance: `LOCALES`/`JA_LABELS` and alternative generation in `scripts/site_header.py`, `syncLocale()` in `site/site-header.js`, raw no-JavaScript assertions and six-locale browser flows.

- Next/handoff: the sales page owns its body journey; the same shared header remains available.
- Alternative/failure/recovery: no missing-locale page is fabricated. A missing link, duplicate link, wrong label/route, off-screen link or failed destination is a failure; the visitor may dismiss and remain on the source page.
- Oracle/provenance: `tests/header-sales.test.cjs` validates all generated pages and stable label metadata; `scripts/check-sales-navigation.cjs` performs 24 locale/viewport/JavaScript flows plus repeated legacy locale changes.

### AC-2.account — account and store handoffs

## Generation and runtime sequence

1. An authored/generated page supplies body/SEO content, `html[lang]`, locale alternates and any legacy `i18n.js` contract.
2. `scripts/site_header.py` classifies eligibility, derives the locale and routes, renders the complete no-JavaScript header, replaces/inserts only the pre-main header area and pins the shared asset key.
3. The browser can immediately operate the native details and links without JavaScript.
4. When JavaScript runs, `site-header.js` marks the header enhanced, synchronizes the outer responsive state, computes scroll offset and synchronizes labels/routes from `html[lang]`.
5. Legacy `i18n.js` may mutate `html[lang]`; `MutationObserver` invokes the same synchronization again. Repeated changes must be idempotent.
6. The visitor activates a local/static or existing external link. No header API, database, worker, telemetry or account write participates.
7. The destination document becomes the next owner and renders its own generated shared header where eligible.

## Recovering header evidence references (design C17)

`scripts/reconcile-header-evidence.cjs` consumes the existing external
`matrix.json` (`results[].layers.*.evidence`) and writes a separate report.
Supply only authorized evidence roots; directories are bounded and symlinks are
not traversed. A matching SHA-256 can repair a relocated reference. A different
image or absent content remains incomplete. Only the explicit historical
`AC-2.work/language/layout/account` alias maps to `AC-2`; unknown and duplicate
IDs remain unresolved. Original statuses, residual risks and source revisions
are preserved. Reference verification is not visual or current-candidate
approval and never declares the original HP purpose complete.

```sh
node scripts/reconcile-header-evidence.cjs \
  --matrix /absolute/evidence/matrix.json \
  --root /absolute/evidence \
  --output /absolute/evidence/new-reference-report.json
node --test tests/header-evidence.test.cjs
```

The exported `reconcileEvidence` consumer also accepts a caller-owned `recover`
adapter. It requests only missing/mismatched content, once per expected hash per
collection. The adapter can collect an existing completed job or perform a
permitted, narrowly scoped reacquisition; it returns `path`, `jobId` and matching
`sourceRevisions`. The consumer validates the file within allowed roots and its
expected hash before adoption. Failure remains local while other evidence is
processed. No manifest-provided command executes, no worker is launched by this
consumer, and no global retry/continuation controller is introduced. CLI
`--receipts` accepts an optional hash-keyed receipt map for collection, not an
instruction to rerun a job. Original receipts and existing reports cannot be
overwritten by the CLI.

Regression fixtures compare path-only failure, hash-based repair, reinjected
wrong/missing content, adapter execution for one missing image out of four,
local adapter failure, repeat collection without duplicate dispatch, source
binding rejection, and path/ID boundaries. These synthetic collector tests do
not establish physical-device, authentication or shared CLI recovery coverage.

## Narrow zoom reflow

In the compact layout, controls wrap when they cannot fit the available row. The brand/menu stay together and language/signup move to the next row only when needed. Tight spacing and the language panel's header-relative anchor preserve reachability in the 390px / 200% CSS zoom fixture. Intrinsic wrapping avoids relying on identical zoomed container-query measurements in Chrome and Safari. The visual order follows the DOM order (brand, menu, account). CSS zoom fixtures are distinct from native browser zoom and physical-device acceptance.
Forward Tab from an open mobile menu toggle explicitly focuses the first navigation item, because Safari can skip nested native summaries. Backward Tab, closed menus, desktop controls and unrelated focus retain native navigation.

Closing the compact outer menu dismisses only its nested dropdowns. A delayed native `toggle` event must preserve a language menu opened immediately after Escape; opening the outer menu still closes all competing dropdowns.
