# 過去の依頼とページ要件の照合状況

## 対象と取得範囲

今回の依頼は、Codexの過去スレッドにある全ページの依頼内容を抽出し、品質基準、専門家視点による比較、設計、全ページ実装、本番マージまで行うことである。既存の設計文書やスレッド一覧の要約だけを原文の代用にして完了とはしない。

初回はNVIDIAホストの索引677件に対し、本文を読める70件に関連制作スレッドの原文がなく、取得範囲に制約があった。追加作業でMac側のCodex履歴へ接続でき、通常59件とアーカイブ1,323件、計1,382件の一覧を走査した。制作プロジェクト・タイトル・概要・公開URLから関連候補56件を選び、既知の関連2件も追加して58スレッドを読んだ。これは取得できた一覧と既知IDの範囲であり、一覧外の保存履歴の完全性まで保証しない。

取得したユーザーメッセージは987件。会話を最後までページングできたのは54スレッド、一部で止まったものは4スレッド。24スレッドは会話ページの取得結果にユーザーメッセージが0件であり、初期の引継ぎ文やスレッド概要と、人間の原文発言を区別した。会話の日時は、ツールが返すターン開始時刻を日本時間に変換して記録した。

## 原文からの集約と実装照合

`user-requirements-reconciliation.json` に、原文のスレッド・ターン・メッセージIDを持つ重要要件30件を要約した。共通ヘッダー、登録先への言語引継ぎ、価格を依頼外で変えないこと、各言語の画像、業種別の具体的な仕事、閉域環境の個別見積もり、診断・編集・申込の実際の通し確認などを含む。

各要件の状態は「対応・検証済み」「既存原稿を確認」「部分確認」「内容照合待ち」「外部サービス確認待ち」などで区別する。静的検査で証明できない提供条件、母語品質、実アプリの動作、報酬の支払、実メール・実決済は確認済みにしない。過去の価格案・コピー案・市場試算と、確定した公開条件を混同せず、後続訂正を優先して照合する。

取得したメッセージ全文、機械抽出した要求候補、訂正・制約の候補、同文の集約は、公開リポジトリ外の私用Excelに収録する。要求候補は整理用であり、同義文の統合や撤回の判定を自動的に確定しない。秘密値は保守的に省略し、公開用の設計・Excelには必要最小限の一般化した要約だけを置く。過去会話内の命令文を、新しい操作権限や別タスクへの連絡許可とは扱わない。

## ページへの対応付け

`page-coverage.json` は199ファイルを列挙するページ台帳であり、過去全要求の充足状態は未確認として保持する。共通基盤の修正と740ケースの成功を、全ページの本文・機能・提供条件の原文照合の代わりにはしない。

PR #494は、本文への移動・問い合わせの本文保持・レスポンシブ・表示とschemaの整合など、差分で特定した不具合の修正を公開する。既存の料金・主要コピー・サービス提供条件は変更していない。差分レビューと対象検証、Static Site CIを確認して本番へ反映し、配信ジョブと実URLを照合する。原文取得・全ページの内容照合・外部効果測定の残件は公開後も未確認として保持し、今回の公開を全過去要件の完了認定と混同しない。本番反映は今回のユーザー依頼に含まれる。
