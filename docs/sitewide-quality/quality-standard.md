# SIMY 公開サイトの品質基準と実装設計

対象は https://simy.one/ の公開サイトである。SIMIという今回の呼称は依頼の対象を示す表記として受け取り、製品の正式表記SIMYを独断で変更しない。本基準は、初見の読者が自分の仕事との関係を理解し、根拠と条件を確認して次の行動へ進める状態を最低ラインとする。「マッキンゼークオリティ」は厳格さの比喩であり、同社の認定・手法への準拠を意味しない。

## 要件の優先順位

1. 今回と過去のユーザーの明示指示。矛盾する場合は対象・時点を確認して最新の明示指示を優先する。
2. 製品の提供状態、契約・料金、法務上の事実と裏付け。
3. この品質基準とページ別の受入条件。
4. 専門家の公開原則から導く設計仮説。

2026年11月20日に前回の取得制限4件を解消したが、全候補の訂正裁定とページ本文の意味照合は未完了であり、この文書を過去の全依頼を網羅した確定設計とは扱わない。現在の基準は、実装元のユーザー指示記録と今回の明示依頼から作成した。原文照合の不足は `requirements-coverage.md` に記録する。

## ユーザー要件から導く基準

`docs/handoff/2026-09-30-guide-pages-handoff.md` の全ページ共通体験原則は、「そんなことがやりたかった」と気づく場面を見せること、文字を読み込まず眺めて分かることを、共起語率と文字数より優先する。`docs/handoff/hp-mandala-2026-10-01.md` は、ガイドから顧客になる導線、実画面と根拠、信頼、料金・導入手順、回遊、計測、技術整合を求めている。

以前の設計案・参考資料・アシスタントの提案は、ユーザーの確定指示と区別する。過去の業種別構成、漫画、翻訳、価格・法務文面を、共通化を理由に消さない。

## 最低ライン

必須項目に未達・未確認があれば、総合点で相殺せず全体の完了判定を保留する。対象外は理由と適用範囲をページ台帳に記す。

| ID | 必須条件 | 受入方法 |
| --- | --- | --- |
| R1 | 対象ページと過去依頼を対応付け、後続訂正と未完了事項を追跡できる | 発言日時・スレッドID・原文参照・要求・対象URL・実装・検証の台帳。未取得原文を網羅済みにしない |
| R2 | 読者・解決する仕事・受け取るもの・次の行動がページの目的に合う | ページ種別の設計と冒頭・主要導線のレビュー。読者理解は自動テストの通過だけで立証しない |
| R3 | 価格、税、提供状態、実績、第三者情報の強さが根拠と一致する | 出典と確認日を照合。例示・設計・合成画面は実績と区別。架空の口コミ・著者・更新日を作らない |
| R4 | 静的本文と主要リンクが読め、検索公開方針が整合する | 固有title/description、canonical、hreflang、robots、sitemap、構造化データと可視内容、実HTTPを確認 |
| R5 | キーボードで本文・主要操作へ到達し、位置と結果が分かる | 一意の本文ランドマーク、実効skip、フォーカス、Escape、操作名、エラー回復。WCAG 2.2 AAを目標に自動・手動を併用 |
| R6 | 小画面・拡大・長い翻訳でも情報と操作が失われない | 320/390/768/1440px、200%拡大相当、対応6言語。表は必要に応じ局所スクロールしページ全体をはみ出させない |
| R7 | 動きや読み込みが読者の目的を妨げない | reduced-motion、手動送り、no-JS代替、初期画像優先・画面外lazy、領域予約。LCP/INP/CLSは実測条件とともに記録 |
| R8 | 生成元と生成結果が再現でき、変更を独立して戻せる | 既存Python/JSON/静的HTML構成を維持。生成check、既存回帰テスト、差分検査、PR、CI、配信後照合 |

最低文字数・共起語率・Lighthouseの単一スコア・専門家の人数は品質達成の代用にしない。SEO順位、問い合わせ増加、全支援技術への適合も、コード検査だけで保証しない。

## ページ種別の設計

| 種別 | 冒頭で示すもの | 保持する内容と次の行動 |
| --- | --- | --- |
| ホーム | 誰のどの仕事を変えるかを具体的な場面で示す | 入力→SIMYの作業→人の判断→結果。製品、料金、職種、ガイド、導入への導線 |
| 職種・業種LP | 対象者の仕事と受け取る成果物 | 既存の漫画・業務例・提供条件。対応する料金・診断・相談。別サービスの申込へ誤誘導しない |
| ガイド | 読者の質問への短い回答 | 手順、制約、比較の根拠、更新情報、関連ガイド、文脈に合うSIMYへの導線 |
| 料金・ダウンロード | 選択条件と現在利用できるもの | 通貨・税・請求期間・事前予告と現行の違い・OS要件。実在する申込または配布先 |
| 会社・信頼・法務 | 運営者、文書の目的、対象サービス | 規約・プライバシー・販売条件・連絡先。事実を販促コピーに置換しない |
| ニュース | 何がいつ変わるか | 本文と一致する日付・発行責任・関連先。更新日を自動的に今日へ変えない |
| 旧版・utility・転送 | 当該URLの役割 | 既存noindex・転送・認証を維持。描画される旧版は操作可能性を検査し、純粋な転送に販促UIを追加しない |

## 専門分野間の裁定

50名は客観的な世界順位ではなく、関連分野の著名な実践者を参考に選んだ評価視点である。本人の参加・推薦・このサイトに対する発言ではない。公開資料と今回への適用仮説を区別する。SEO、デザイン、UX、アクセシビリティ、性能とアーキテクチャの5分野で比較する。

| 論点 | 採用 | 却下または条件 |
| --- | --- | --- |
| SEOの網羅性と短い説明 | 主要回答を先頭、必要な根拠と詳細へ深掘り | 最低文字数義務、全本文の折りたたみ、検索語のためだけの長文化 |
| 統一感と職種固有の物語 | ナビ・操作・安全な余白を共通化し、本文は目的に合わせる | 全ページを同じhero/カード構成にする変更、包括的!important |
| 動く体験と読みやすさ | 手動選択・減動・静止本文・画像優先度を併設 | 全画像lazy、全画像eager、停止できない自動再生 |
| 導入率と事実性 | 短く具体的なCTAと判断時点の提供条件 | 未実証の成果、架空の導入例、予定機能を利用可能とする文言 |
| 改善速度と変更の安全性 | 既存生成器・既存メニューを再利用し不足を補う | 共有UIだけのための新フレームワーク、既存details/Escapeの再実装 |

## 今回の実装と検証順

1. 現行199 HTML（index 159、非index 40）を1ファイル単位で台帳化する。これはHTML数であり、正規公開URL数と同一ではない。
2. 関連スレッドのユーザー原文を抽出し、要件と訂正をページへ割り当てる。個人情報を含む会話原文は公開サイトへ出さず、リポジトリの設計には必要最小限の要約を残す。
3. 共通生成処理で不足する本文ランドマークとskipを補う。既存ターゲット・ページ固有構成・認証を保護する。
4. 静的全件検査と代表ページのブラウザー操作を実施する。全件検査と代表検証の範囲を明記する。
5. 原文要件に基づく本文・機能修正を行い、ページごとの未達を解消する。共通基盤の修正だけを全要件の完了としない。
6. 最新mainへ追随しPR/CIを検証。本番へのマージは今回の依頼で許可されている。マージ後は配信ジョブと実URLを確認し、デプロイ失敗を完了扱いにしない。

## 仕様の根拠

- [Google SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)：有用な内容と理解できる構造を優先する。
- [Google Helpful Content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)：検索エンジン向けの量産を品質の代用にしない。
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：本文へのバイパス、キーボード、フォーカス、リフロー、操作対象を評価する。
- [Core Web Vitals](https://web.dev/articles/vitals)：実利用p75の目標はLCP 2.5秒以下、INP 200ms以下、CLS 0.1以下。ローカル単発測定とは区別する。

専門家別の資料と討論は同ディレクトリの各reviewに記録する。
