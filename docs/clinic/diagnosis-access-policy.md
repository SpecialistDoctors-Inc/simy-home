# 診断対象の権限確認

状態：設計。認証・権限確認機能は未実装。

同一IPは同一人物を意味しない。院内・医師会・代理店の共有回線を一律拒否せず、ログイン利用者と対象医院の権限を主な制御軸にする。

1. URL入力直後には対象を取得できたかと簡易結果を返す。
2. 詳細診断・PDF・編集体験の開始前にメール認証を行い、医院との関係を確認する。医院ドメインのメールだけでサイト所有者と断定しない。DNS TXT、HTML確認ファイル、SIMYが確認した委任で対象ドメインへの権限を付与する。フリーメール・複数院・代理店利用を考慮する。
3. 利用者と許可したドメインをサーバーで関連付ける。レポート取得・PDF用データ・プレビュー・編集のAPIで毎回検証する。匿名NDJSONのpartial/resultに詳細を返さない。画面の非表示だけで保護済みと扱わない。
4. 新しい医院への切替にはその医院への権限を求める。認証済みアカウント、短期間に切り替えた対象数、IP等を補助情報にし、大量アクセスには追加確認を使う。IP・Cookie・端末指紋だけで人物を断定しない。
5. 編集の時間あたり回数上限は復活させない。権限確認は対象医院と利用者の関係に適用し、正当な編集の反復を妨げない。

受入では、匿名APIから詳細を取得できないこと、別アカウント・別医院のIDで取得や編集できないこと、同一院内IPで正当な複数利用者が使えること、フリーメール・代理店の委任と失効、再読込、ドメイン確認時のSSRF対策を検証する。

参考：[Googleの所有権確認](https://support.google.com/webmasters/answer/9008080?hl=en)、[Turnstileのサーバー検証](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[Cloudflare rate limitingの条件](https://developers.cloudflare.com/waf/rate-limiting-rules/parameters/)。
