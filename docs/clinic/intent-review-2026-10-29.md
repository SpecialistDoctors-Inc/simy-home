# 医院の体験としての再点検

判断軸は、説明の網羅性ではなく「自院の問題として気づく→診断する→改善を実際に試す→費用を理解して任せる」に置く。

| 意図とのずれ | 改善 |
| --- | --- |
| 普通の文章で更新できる案内なのに、体験では命令書式を要求する | お知らせ追加・文章差し替えを選び、普通の文章を入力する。1クリックの休診例も用意。自由なAI編集とは表示しない |
| 携帯で入力欄がプレビューを押し出し、どこが変わったか見失う | プレビューと入力を切り替え、反映後はプレビューを表示する |
| 編集体験を閉じる以外の次の行動がない | 料金へ進む操作と、対象URL・医療機関名等の欄が入った移管相談メールを用意。送信はしない |
| 診断後、もう一度医院URLを入れる必要がある | 未入力の再現URLには診断対象を引き継ぐ。利用者が入れた別URLは上書きしない |
| 上部PricingとSign upから別サービスの料金・登録へ移動する | HP管理の料金・医院URL入力へ接続。既存SIMYアプリへの入口は明示して区別する |
| 過去の事故公表の数を医院の問題数と誤解しやすい | 部品の旧版・脆弱性と、関連する公表事例の見出しを区別する |

漫画、業界の指定、料金、同意、01〜03の全件表示・問題優先、PDF、移管手順、権利確認は維持する。既存のAI実行・Sheets・Stripe等を、このUI改善をもって稼働済みとは扱わない。
