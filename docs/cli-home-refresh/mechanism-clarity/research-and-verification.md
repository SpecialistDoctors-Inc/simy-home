# SIMYとAIの役割を明確にする修正

2026-11-17。ユーザー指摘：SIMYを使うとなぜボタンを直せるのか、ClaudeやCodexだけではなぜできないのかが分からない。

## 確認した事実

- SIMY CLI v1.2.11（ソースコミット9146fe2ced9f79571210f087665d7e94795dfdb9）のREADME Delivery Loop節（140–191行）では、AIが完了条件・確認方法・進捗を報告し、Stop hookが残る条件を見て続行する。SIMYが独立にブラウザを操作して不具合を検出する仕組みではない。
- [Claude Code公式](https://code.claude.com/docs/en/how-claude-code-works)：情報収集・実行・検証を繰り返すエージェント。単体でも修正とテスト、継続作業が可能。
- [Codex Goals公式](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)：目標・完了条件・確認できる根拠を使った継続作業が可能。完了条件や継続をSIMYだけの機能とは訴求しない。

## 掲載内容

- 冒頭で、実装・修正・操作確認はCodex / Claude Code、SIMYは進行を補うと明記。
- 4コマを具体的なCodexの例に変更。修正と操作結果の報告はCodex、未確認の条件を残して会話が終わる場面ではSIMYが同じ会話へ続行を促す。公開を判断するのは利用者。
- 役割表と、コード修正だけで会話が終わった場合の例を追加。AIから報告された完了条件・進捗に基づくことを明記。
- FAQで、両ツール単体でも実装・確認・継続ができ、Codex Goalsとも重なることを明記。SIMYの訴求は両ツールでの共通の進め方と、複数の仕事・判断待ちをアプリで追うこと。
- モバイル表示の説明例であることと、実機確認が必要ならその条件・手段も必要なことを明示。AI側のツール・権限、進展がない場合の停止、成功を保証しないことも説明。
- 機器描写を修正したv2イラストは維持。会話の文字はHTMLの20px。価格・閉域対応・紹介制度は変更しない。
