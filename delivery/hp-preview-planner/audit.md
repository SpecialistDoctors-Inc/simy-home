# HP preview editor runtime audit

The live test path starts at the regular clinic and law firm forms on `simy.one`. Both send the consented URL to the Sites rebuild API, then send the current DOM inventory, conversation and available attachments to the shared edit API. The edit API queues a job for the edit runner, which imports the planner and validates its bounded response. The browser applies the operations to a local sandbox.

| Stage | Finding and action |
| --- | --- |
| Form and examples | Both regular forms use the entered URL and pass the conversation to the same API. On `simy.one`, sample buttons prefill editable text. The law firm sample has fictional content and explicit sample presentation. These are display content. |
| Old browser edit path | The current bundle still exported an unused Japanese command parser and a generic notice banner. Removed those exports and the fallback renderer. |
| Target inventory and DOM mutations | Heading, card, notice field and metadata heuristics still used class words or class prefixes. Inventory now uses semantic headings, accessible section names, short adjacent labels and repeated structure. Notice insertion uses the date and text structure and clears the old text outside chosen fields. New photos and sections derive their presentation from the local layout. |
| Photo selection | The browser matched attachment filenames against the message and sampled the largest loadable site image. Multiple attachments and existing site images now use one explicit planner-selected ID. The single-image and upload limits, same-origin canvas rules, and retry budget still apply. |
| Edit worker and planner | The installed worker dispatches by job kind and validates the plan, then retries bounded invalid output once. The planner now derives copy language and date display from the request and document. It can request a listed existing image ID and rejects IDs for unrelated nodes. |
| Gateway and reconstruction | The available route and bridge sources show origin checks, consent, bounded input, job admission, and safe HTML reconstruction. The regular public contract covers the homepage. The available checkout predates the production interactive protocol. Production verification exercises the actual route; it does not establish line-by-line source provenance for the gateway. |
| Separate Sites entry | The public `simy-website-diagnosis.tetsuo.chatgpt.site/hp-management/clinic` serves `preview-edit.js?v=3d38195ce03c` and `clinic-rebuild.js?v=481382f65b2c`. The served assets still contain keyword-based editor logic and an example that submits a fixed clinic request. The Sites connector exposes public metadata (version 29) but returns `Sites project not found` for version listing and source write access. The signed-in portal redirects an anonymous request, so its served editor could not be verified. Do not publish the earlier checkout over the live Sites deployment. |
